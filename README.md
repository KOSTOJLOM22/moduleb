# Модуль Б — навигация РМК-2

Автономный проезд от старта до цели и обратно с обходом препятствия лидаром.

Код (`main.py`) по умолчанию настроен **на конкурсный день**: сетка 5×5,
нумерация маркеров по столбцам ("col_major") — как на реальном поле финала
(эталон, см. `pole-finala-profil.md` в проекте). Симулятор, который сейчас
реально есть и работает — старый мир 6×6. Когда появится официальный
симулятор поля 5×5 — замени им шаг 1 ниже, код (шаг 3) трогать не придётся,
он уже под 5×5.

## 1. Запуск симулятора

Пока что — проверенный мир 6×6:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 launch ar_webots_fms_ros2 module2.launch.py
```

Когда получишь мир 5×5 от организаторов — впиши его лаунч-файл сюда вместо
`module2.launch.py`.

## 2. Запуск Rviz2 (опционально)

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 launch ar_webots_fms_ros2 rviz_rmc2.launch.py
```

## 3. Запуск задания (миссия)

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
python3 main.py --ros-args -p start_id:=0 -p target_id:=24
```

Команда без параметров сетки — это и есть эталон 5×5/col_major по умолчанию.
Движение — **Enter** в терминале после вывода маршрута. Второй раз — после
появления обратного маршрута.

**Важно, пока симулятор ещё 6×6 (шаг 1), а код уже 5×5 (шаг 3):** это две
разные раскладки маркеров, вместе они не сойдутся — команда выше на
нынешнем 6×6-мире поедет не в те клетки. Если хочешь погонять миссию именно
на нынешнем 6×6-симуляторе для проверки (не для финала), переопредели сетку
явно:

```bash
python3 main.py --ros-args \
  -p grid_rows:=6 -p grid_cols:=6 -p grid_order:=row_major \
  -p start_id:=0 -p target_id:=22
```

Когда шаг 1 заменится на настоящий мир 5×5 — команда из этого раздела (без
параметров) сама совпадёт с ним, ничего менять в коде не нужно.

## Переход на реальное поле (финал)

Сетка и нумерация в коде (шаг 3) уже совпадают с полем финала — их менять не
нужно. Единственное, что отличается на реальном роботе — топики: отдельная
камера нижнего обзора и раздельные лидары вместо симуляторных. Переопредели
их явно при запуске `main.py`, ничего не меняя в коде:

```bash
python3 main.py --ros-args \
  -p aruco_topic:=/RMC2/camera_bottom/aruco_id \
  -p scan_topic:=/RMC2/scan_front \
  -p start_id:=0 -p target_id:=<целевой_id>
```

Пояснения:

- `aruco_topic` — на реальном роботе ArUco-метки видит отдельная камера
  нижнего обзора (`/RMC2/camera_bottom/aruco_id`), а не общий топик
  `/RMC2/aruco_id`, как в симуляторе.
- `scan_topic` — на реальном роботе используем только передний лидар
  (`/RMC2/scan_front`). Общий `/RMC2/scan` там уже объединяет передний и
  задний лидары и включает в себя собственный корпус робота — для навигации
  не годится.
- `marker_spacing` (по умолчанию `1.0` м, шаг сетки в метрах) и точное
  расположение стартовых точек/чек-пойнтов на финальном поле по документации
  конкурсного задания **пока не подтверждены измерениями** — проверить перед
  финалом. Список открытых вопросов — в `pole-finala-profil.md`.

Все остальные параметры (`max_linear`, допуски выравнивания, объезд
препятствий и т.д.) не зависят от поля/топиков и не требуют переопределения.

## Аварийная остановка

```bash
ros2 topic pub /chvt/emergency_stop std_msgs/Bool "{data: true}"  --once
ros2 topic pub /chvt/emergency_stop std_msgs/Bool "{data: false}" --once
```
